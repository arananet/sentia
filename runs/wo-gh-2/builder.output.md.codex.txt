# Sentia design system

Identity is governed by brand/BRAND.md. This system applies that identity to
the launch page: a small physical instrument, drawn at architectural scale.
Sentia Patch One is the object; Sentia Cloud receives its measurements; the
Sentia MCP Server makes those measurements available to assistants.

## Tokens

Paper #FAFAF6 occupies roughly 90 percent of the surface. Ink green #12211C
forms text and instrument outlines. Signal teal #0E7C66 marks links, labels
and the Find My network and LoRaWAN paths. Coral #FF6B4A is reserved for the
status LED and alert dots. Soft mint #EFF4EE is a rare panel fill; hairline
#DFE7DF divides information. Body text uses #4A5D54; secondary labels use
#53685C for legibility on paper. White is reserved for the physical patch.
No decorative gradients. One diffuse shadow beneath the hero object only.

## Type scale

Space Grotesk at weight 300 is the display face. The hero runs from 56 to
144 px with 0.96 leading and -0.055 em tracking. Section titles run from
40 to 88 px with 1.04 leading and -0.04 em tracking, limited to 18 characters
per line where space permits. Data values run from 32 to 56 px. Inter body
text is 17 px with 1.65 leading; introductory text is 18–20 px, at most
54 characters per line. System mono labels are 11 px, uppercase, with
0.16 em tracking. Never shrink body copy to fit a composition.

## Spacing rhythm

Use an 8 px base: 8, 16, 24, 32, 48, 64, 96, 128, 160. The page container
is at most 1440 px wide, with fluid 24–80 px gutters. Sections have 96–160 px
vertical padding. A title, its introduction and its illustration form one
idea; detailed lists follow with generous separation. Hairlines provide
structure without enclosing every item in a card. Technical examples and
tables remain dense enough to scan, with scrolling contained locally.
Fixed margins, padding and gaps use multiples of 8 px, including the bounds
of fluid spacing. One-pixel border overlaps and diagram coordinates are
optical geometry rather than content spacing.

## Hero art direction

Place the existing headline at large scale on the left and a 38 mm disc
at exhibition scale on the right. Keep introductory copy beneath the
headline. The patch is paper white, concentric, precise: fine rings,
radial registration marks, a small coral LED and a dimension line. A
single soft grounding shadow gives it physical presence. The caption is
an engineering annotation. No invented features or decorative circuitry.
Below 1000 px, stack the headline, object and supporting copy. At narrow
widths, preserve the whole object and give text the full available width.
The exploded view and network paths remain quiet technical drawings.

## Motion

Existing reveal hooks stay intact. Fades and small rises use 800 ms ease-out.
No scale animation, bounce, glow or perpetual hero movement. Hover changes
are small color or hairline changes. Reduced motion disables CSS reveals
and smooth scrolling, and hides the moving packet dot; the measurements
and existing controls continue to operate. Static content must remain
readable without JavaScript through a noscript style override. With scripting
enabled, reveal elements begin at zero opacity and 16 px below their final
position; the existing observer adds the visible state. Reduced motion keeps
both the initial and revealed states visible and stationary.

## Launch page quality bars

- S1: This document precedes implementation. CSS implements its palette,
  type hierarchy, spacing and physical hero composition.
- The first view has one focal object and a headline substantially larger
  than body copy. The page has breathing room at 1440, 1024, 768 and 375 px.
- S2: Preserve every section, content fact, SEO/GEO output, client hook,
  simulation control and dashboard action. Measurements keep their units.
- At 320 px and at browser zoom, text wraps without page overflow; wide
  technical data scrolls in its own region. Keyboard focus is visible.
- S4: Implementation touches only src/page.js and this document. API, MCP,
  codec, routing and data behavior are outside the presentation scope.
- S5: Keep the existing calm copy and exact product and network names.
  Wellness framing and the medical disclaimer remain visible.
- Run the full scenario suite. Visual quality and S3 model provenance are
  assessed by the independent review stations; passing tests is not approval.
- S6: At small widths retain a 56 px hero minimum and 17 px body minimum.
  Use #53685C for SVG annotations and paper for the simulation toggle.
  Check the hidden reveal state, 800 ms ease-out transition and motion fallback.
# Sentia brand

One page of rules. Everything Sentia publishes follows it: the site, the dashboard, API field names, MCP tool descriptions, README, llms.txt and the social card.

## Naming

- The product is always **Sentia Patch One**. Never "SentiaPatch", never "the Sentia patch" in headings, never "Patch One" alone on first mention.
- The platform is always **Sentia Cloud**.
- The assistant interface is always the **Sentia MCP Server**. Its endpoint is /mcp and its server name is sentia-mcp.
- Networks are written **Find My network** and **LoRaWAN**. Never "LoRa" alone when the network is meant, never "Apple network" or "iTag network".
- Measurements keep one name and one unit everywhere: skin temperature in °C, hydration index from 0 to 100, activity in steps equivalent, sweat rate in µL/min, battery in percent.
- API and MCP field names follow the same words: temperatureC, hydrationIndex, activitySteps, sweatRateUlMin, batteryPercent.

## Tagline

"Measurements that find their own way home."

Definition sentence, used verbatim where a one line definition is needed:
"Sentia Patch One is a 38 mm adhesive sensor patch that measures skin temperature, hydration and activity for up to 14 days without a phone."

## Palette

- Paper: #FAFAF6 (the background, roughly 90 percent of every surface)
- Ink green: #12211C (text and the patch drawing)
- Signal teal: #0E7C66 (structural accents only: links, labels, network path lines)
- Coral: #FF6B4A (micro accents only: the patch LED, an alert dot, at most one word in the hero)
- Soft mint: #EFF4EE (rare panel fill), hairline: #DFE7DF

No gradients except a barely visible radial warmth behind the hero patch. No drop shadows except one very soft, wide shadow under the patch visual.

## Typography

- Display: Space Grotesk, light weights, very large, tight leading.
- Body: Inter, quiet gray green.
- Data and labels: system mono, small, uppercase, wide tracking.
- Whitespace is the design. One idea per viewport. If a section feels full, remove elements until it breathes.

## Voice

Calm, precise, metric first. Short declarative sentences. State what the thing is and what it does, with numbers.
Never use hype words: revolutionary, cutting edge, game changer, seamless, supercharge, unlock.
Wellness and monitoring framing only. Sentia Patch One is not a medical device, and copy says so plainly in the FAQ and the footer.

## Logo mark

A plain disc: one thin ink circle, a smaller concentric ring, and a single coral point at the upper right edge for the LED. No letters inside the mark. The wordmark is the name "Sentia" set in Space Grotesk next to it.

## Motion

Slow and physical. Fades and rises of 600 to 900 ms, ease out. The demo packet drifts like a pulse. Nothing bounces, nothing glows, hover states barely darken a hairline.

function handleApi(path, url) {
  const seg = path.split('/').filter(Boolean); // ['api', ...]
  if (seg[1] === 'patches' && seg.length === 2) {
    return json({ patches: fleet() });
  }
  if (seg[1] === 'patches' && seg.length === 3) {
    const patch = getPatch(seg[2]);
    if (!patch) return json({ error: 'patch not found', id: seg[2] }, 404);
    return json(patchStatus(patch));
  }
  if (seg[1] === 'patches' && seg.length === 4 && seg[3] === 'measurements') {
    const patch = getPatch(seg[2]);
    if (!patch) return json({ error: 'patch not found', id: seg[2] }, 404);
    const hours = Math.min(24, Math.max(1, Number(url.searchParams.get('hours')) || 24));
    return json({ patchId: patch.id, hours, points: measurements(patch, hours) });
  }
  if (seg[1] === 'alerts' && seg.length === 2) {
    return json({ alerts: alerts() });
  }
  if (seg[1] === 'network' && seg[2] === 'stats' && seg.length === 3) {
    return json(networkStats());
  }
  return json({ error: 'route not found', path }, 404);
}

  async fetch(request) {
    const url = new URL(request.url);
    const path = url.pathname;
    const origin = url.origin;

    if (path === '/mcp') {
      if (request.method !== 'POST') return json({ error: 'method not allowed, use POST' }, 405);
      return handleMcp(request);
    }
    if (path.startsWith('/api/')) {
      if (request.method !== 'GET') return json({ error: 'method not allowed' }, 405);
      return handleApi(path, url);
    }
    if (path === '/' || path === '/index.html') {
      return text(renderPage(origin), 'text/html; charset=utf-8', {
        link: `<${origin}/llms.txt>; rel="describedby"; type="text/plain"`,
      });
    }
    if (path === '/browser-codec.js') return text(BROWSER_CODEC_JS, 'application/javascript; charset=utf-8', { 'cache-control': 'public, max-age=3600' });
    if (path === '/client.js') return text(CLIENT_JS, 'application/javascript; charset=utf-8', { 'cache-control': 'public, max-age=3600' });
    if (path === '/og.png') return png(OG_PNG_B64);
    if (path === '/apple-touch-icon.png') return png(ICON_PNG_B64);

  },

const rules = (() => {
  const out = [];
  const walk = (src, media) => {
    const re = /([^{}]+)\{([^{}]*)\}|(@[^{]+)\{((?:[^{}]*\{[^{}]*\})*[^{}]*)\}/g;
    let m;
    while ((m = re.exec(src))) {
      if (m[3]) {
        if (/^@media/.test(m[3].trim())) walk(m[4], m[3].trim());
      } else {
        out.push({ media, selector: m[1].trim(), body: m[2] });
      }
    }
  };
  walk(pageCss.replace(/\/\*[\s\S]*?\*\//g, ''), '');
  return out;
})();
