## The model (the heart of this spec)

The model lives in src/take-apart-model.js as a pure ES module with no DOM and no rendering imports, imported directly by the node tests. Its browser twin is served at /take-apart-model.js following the codec pattern of this codebase (src/codec.js and src/browser-codec.js): the same logic carried as browser source text in src/take-apart-model-browser.js, with a test asserting both surfaces return identical outputs at the sampled inputs, so the two can never drift silently.

Layers and thicknesses. The five layers, top to bottom, are the FACTS.layers of src/facts.js, in that order and with those names: Top cover, Comfort foam, Sensing and processing board, Adhesive layer, Release liner. The model assigns each layer a study thickness in millimetres: Top cover 0.6, Comfort foam 0.7, Sensing and processing board 0.5, Adhesive layer 0.4, Release liner 0.3. The thicknesses sum to exactly 2.5, the product profile stated in src/facts.js. A test asserts the sum, asserts the model layer names and order equal FACTS.layers, and asserts every thickness is a positive number.

Stack geometry. Height index i counts from the bottom of the stack: Release liner 0, Adhesive layer 1, Sensing and processing board 2, Comfort foam 3, Top cover 4. GAP_MM is 3.0. The model function layerCenterMm(layer, t) returns the layer centre height in millimetres: the assembled centre (the sum of the thicknesses below the layer plus half its own thickness) plus t times i times GAP_MM. Layer positions derive only from t through this function; nothing else moves a layer vertically. A test asserts that at t=0 every adjacent pair sits flush: the top face of the lower layer equals the bottom face of the upper layer within 0.001 mm, no overlap and no gap beyond that tolerance. A test asserts that at t=1 each adjacent centre distance equals its assembled centre distance plus GAP_MM. The renderer scales vertical millimetres by one named constant, Z_SCALE 8, for legibility; the constant never enters the model.

Footprint. The study footprint is FOOTPRINT_MM 36 square with CORNER_RADIUS_MM 9, stated here as study model numbers (the product states only its profile). Horizontal positions are in millimetres and are not scaled.

Wear state. Wear time h is in hours, clamped to 0..336 (the 14 day wear). The model exports pure functions:
- wearDay(h): min(14, floor(h / 24) + 1).
- skinTempC(h): 36.55 + 0.35 * sin(((h mod 24) - 6) * PI / 12).
- hydrationIndex(h): round(66 + 8 * sin(((h mod 24) - 9) * PI / 12) - 6 * (h / 336)), clamped to 0..100.
- batteryPct(h): round(100 - 88 * (h / 336)).
- tempSeries(): 57 samples of skinTempC, one every 6 hours from 0 to 336.
- gaugeReadout(h): the exact display strings the page shows for the four gauges: skin temperature formatted with one decimal, hydration index and battery as integers, wear day as an integer. The page renders gauge text only from gaugeReadout. No gauge number is typed into markup or into the page script by hand.

Tests assert: batteryPct(0) is 100 and batteryPct(336) is 12; batteryPct never increases as h grows across the sampled range; wearDay(0) is 1 and wearDay(335) is 14; hydrationIndex stays within 0..100 across the sampled range; skinTempC(12) is greater than skinTempC(0); tempSeries has 57 entries whose first and last equal skinTempC(0) and skinTempC(336); gaugeReadout at the sampled hours carries exactly the model values (the temperature string parses back to skinTempC within 0.05 and the integer strings equal the model integers).

Focus state. focusIndex names one layer or none. The scene state is a pure function of (t, h, focusIndex, xray). FOCUS_LIFT_MM is 5.0, ASIDE_MM is 8.0, FADE_OPACITY is 0.35 and XRAY_OPACITY is 0.15. When a layer is focused: the focused layer lifts by FOCUS_LIFT_MM above its layerCenterMm position; every other layer steps aside horizontally by ASIDE_MM, layers below the focused one in the stack toward negative x and layers above it toward positive x; non focused layers render at FADE_OPACITY. The model exports focusTransform(layer, t, focusIndex), returning the vertical lift and horizontal aside in millimetres, and materialState(layer, focusIndex, xray), returning the composed opacity: the fade rule and the x ray rule compose multiplicatively for the cover, and the fade alone applies to the other layers. Tests assert the focused lift value, the aside signs for layers above and below the focus, the fade value, and the composed cover opacities: 0.15 when the cover is focused or unfocused with no fade in play and x ray is on, 0.0525 when the cover is faded by another layer's focus and x ray is on, and 1 when nothing applies.

X ray. When xray is on, the top cover renders at XRAY_OPACITY so the sensing and processing board shows through it. Only the cover is affected.

Quality steps. The model exports qualityFor(env), a pure function of an environment record (devicePixelRatio, hardwareConcurrency, coarsePointer) returning pixelRatioCap, shadowMapSize and panelUpdateHz in three tiers: the full tier caps the pixel ratio at min(devicePixelRatio, 2) with shadowMapSize 2048; the reduced tier (hardwareConcurrency at most 4, or coarsePointer true) caps the pixel ratio at 1.5 with shadowMapSize 1024; the lowest tier (hardwareConcurrency at most 2) caps the pixel ratio at 1.25 with shadowMapSize 0 (shadows off). panelUpdateHz is 4 in every tier. The page applies the returned values: gauge and panel DOM updates happen at most panelUpdateHz times per second, and the chart redraws only when the displayed wear hour changes by at least 0.25. Tests assert qualityFor returns the stated values for stated environment records covering each tier, including the boundary records (concurrency exactly 4 and exactly 2, a coarse pointer with high concurrency).

## The scene

- Five separate meshes, one per layer, procedural geometry only: rounded box geometry built in code from the library's geometry primitives or a small rounded box helper written for this page. No downloaded models, textures, images or fonts. Materials are colors and roughness values stated in code.
- Layer colors stay in the brand family: the cover warm white, the foam pale warm gray, the board the brand ink green with teal accents, the adhesive layer translucent pale, the release liner the lightest gray. ## The console and the experience

- Layout at desktop width: the title and the main live number (skin temperature, large) at top left; the 3D window in the centre; a control bar holding the separation slider (t from 0 to 1), the wear slider (h from 0 to 336, labeled by the wear day from the model), five layer buttons labeled with the FACTS.layers names, the x ray toggle, and three camera buttons labeled Hero, Top and Side. The four gauges (skin temperature, hydration index, battery, wear day) and the temperature chart sit in a panel with the window. The chart is a canvas drawn from tempSeries with a marker at the current wear hour. Every number in the console comes from gaugeReadout or tempSeries.
- Orbit and zoom: drag orbits the camera around the stack and scroll zooms, with damping; the camera never dips below the ground plane.
- Layer buttons: pressing one focuses that layer under the focus rule and raises t to at least 0.55 if it is lower, so the focused layer visibly separates. Pressing the focused layer's button again releases the focus.
- Camera buttons set stated positions in millimetres, all looking at the stack centre point (0, 10, 0): Hero at (52, 42, 62), Top at (0, 95, 1), Side at (95, 18, 0).
- Callouts: one per layer, a thin leader line from a margin label to an anchor point on the layer's edge, drawn in an SVG overlay above the canvas and repositioned as the scene moves. Labels sit in the left and right margins and never cover the layer they name. The focused layer's callout takes the teal accent. Below 720 px viewport width the overlay hides and the layer buttons carry the naming.
- The tour: the page watches for interaction. After IDLE_SECONDS (20) with no pointerdown, wheel, keydown or touchstart, the tour runs by itself. A visible on screen cursor, a small ring element, walks to each control and presses it, stepping through the beats in order: Assemble (t to 0, focus none, x ray off, wear to hour 0), Explode (t to 1), Isolate the board (focus the Sensing and processing board), X ray (x ray on), Settle (x ray off, focus none, t to 0.35, wear to hour 156). Each beat holds about 2.4 seconds. Any interaction stops the tour at once, hides the cursor and restarts the idle timer. The page root carries a data-tour-beat attribute naming the current beat (assembled, apart, board, xray, settle, or off) so the evidence pass observes the tour without guessing. A query parameter tour=fast shortens IDLE_SECONDS to 1.5 and the beat hold to 0.9 seconds; it exists for the evidence pass and is a stated feature of the page. If the visitor's system prefers reduced motion, the tour does not start on its own and transitions are instant.

# Teardown

One machine, one page. The visitor sees the thing run, presses a button, and the part doing the work opens up while the gauges around it read the real numbers. Left alone, the page tours itself with a cursor. The same code records a film of the tour, frame by frame, with a score built on the same timeline.

`SKILL_DIR` below is the folder this file lives in. Builds and renders go to `./teardown-out` of the folder you run from.

## First run

```
cd "$SKILL_DIR" && npm install && npx playwright install chromium
```

The pages need nothing else. The video needs `ffmpeg` on PATH and the score needs Python 3 (standard library only). Set `FFMPEG`, `PYTHON` or `CHROMIUM` to point at other binaries.

## How a machine is built

One folder per machine, split by job. The examples follow this exactly:

| File | Job |
|---|---|
| `kin.js` / `gear.js` / `jansen.js` | The math. Real dimensions in real units, one input (crank angle, stroke, wind) and every pose and readout as a function of it. No three.js in here. |
| `engine.js` / `gear.js` / `beast.js` | The geometry, built from code: lathed parts, tubes, instanced links. `update(input)` poses it. |
| `stage.js` | Studio, lights, shadows, post (GTAO, bloom). `frame(state, cam)` draws one frame. |
| `console.js` | The overlay: fixed 1600 x 900 CSS layout of panels, charts, toggles, callouts with leaders. `update(state)` redraws it from the frame's state. |
| `film.js` | A `SCRIPT` of operator moves (views, isolate, cutaway, throttle) and `render(t)` as a pure function of time. |
| `live.js` | The same machine in real time: buttons, sliders, orbit, zoom, keys. With no input it plays `film.js`'s script as an auto tour with a cursor; any click, drag, wheel or key hands control over, 25 s of quiet hands it back. |
| `score.py` | The sound on the film's timeline. |

For a machine outside `SKILL_DIR`, make a folder with a `main.js` and import the kit by name: `import {runSim} from 'teardown-kit/runtime.js'`. Build it with `node "$SKILL_DIR/sims/build.mjs" ./my-machine`.

## Rules that decide whether it works

1. **Start from a reference, never from imagination.** A photo, a cutaway drawing from a manual, a clip of the real thing. Build against it and compare frame by frame. Machines invented from a sentence come out generic every time; the same model rebuilds a real one closely when it has something to match.
2. **Real numbers, one source.** Get the real dimensions first (bore, stroke, tooth count, link lengths). Every gauge, chart and label reads from the same function that poses the parts, so nothing on screen can disagree with the motion. Check one by hand: in the Cessna, 32 teeth × 4 mm module is a 128 mm pitch diameter, and half its circumference is the 201 mm stroke.
3. **One input drives everything.** Pose from the crank angle, the stroke or the wind. Nothing is keyframed by hand, so the film, the live page and the score never drift.
4. **The part doing the work opens up.** Isolate it, cut it, x-ray it. A camera that goes inside is worth more than ten orbits.
5. **Light studio, one accent.** Pale backgrounds read in a feed; dark ones lose the first second. The accent marks the thing that is changing. Watch near-white parts on a pale backdrop: give them an ink outline or a darker ground.
6. **Pick the camera for the mechanism.** A planar linkage seen face-on collapses into a lattice; a 3/4 view along the spine keeps every leg readable.
7. **Fix collisions with a number.** When a part pokes through another, scale or move it in the parameter block. Never hide it with the camera.

## Live page rules

- **Test on an integrated GPU.** A page that runs at 60 fps on a desktop card can drop to 15 fps on a laptop's built-in one. The examples carry quality tiers (`TIERS` in `live.js`): no AO, lower pixel ratio, smaller shadow maps, panels redrawn every other frame. Find the expensive shader first: a displacement computed 5 times per vertex costs more than every tier together.
- **Warm the shaders.** `kit/warm.js` compiles every program in parallel before the first frame, so the page never freezes on first draw.
- **Keep the page under 1 MB.** Link crawlers (X, Slack) read the share card from the HTML and give up on a 15 MB page. Big models go out as files next to the page: `build.json` → `{"external": {"heavy.glb": "light.glb"}}`.

## render(t) contract

```js
import {runSim} from '../kit/runtime.js';

const DEFAULTS = {duration: 20, fps: 60, hud: {enabled: false}, director: {enabled: false}};

runSim(DEFAULTS, async ({cfg, canvas, capture}) => {
  // build the scene, precompute anything stateful
  return {render(t) { /* draw frame t from scratch */ return {}; }, resize() {}};
});
```

- `render(t)` is pure: no `Math.random` (use `rng(seed)` from `kit/util.js` at setup), no `Date`, no state carried between frames. Capture calls it at arbitrary times.
- Anything that moves by its own rules (agents, particles) is simulated once at load into typed arrays; `render` only reads them. A quantity integrated over time (the Strandbeest's crank under a changing wind) is integrated in closed form or tabulated at load.
- Every beat goes into `<name>-film/timeline.json` in seconds. The score reads the same file.
- Frame 0 is the thumbnail. It must already show the machine.

## Review loop

You cannot watch the video; you can look at frames. Never report a machine as done without reading sheets of the current render.

1. `--stills beats`: one tile per timeline beat, 0.3 s after it, each labelled `t=`.
2. Read every tile against the checklist below.
3. Zoom in: `--stills every:0.2 --from A --to B` for a transition, `--still T` for one full frame.
4. Fix, rebuild, go back to 1. Stop when a full pass finds nothing.
5. Final: `node "$SKILL_DIR/sheet.mjs" --video <final.mp4> --timeline <timeline.json>` and read that too: it shows what the encoder wrote.

Checklist:

- **The mechanism.** Every part that should touch touches; nothing passes through anything; the numbers on the panels match the pose.
- **Composition.** One focal point per frame. Nothing important within 60 px of an edge. Labels never cover the part they name.
- **Type.** Nothing clipped. The key readout reads at phone width.
- **3D.** Bloom eats detail: keep emissive layers under 1.0. Near-white surfaces blow out. Glossy metal under a low light streaks: roughness ≥ 0.45 and envMapIntensity ≈ 0.5 on big surfaces.
- **Timing.** Each state holds long enough to read: 1 s for a short phrase plus 0.25 s per word beyond three.

## three.js traps the examples already hit

- `smoothstep(a, b, x)` with `a > b` returns 0 on Windows (ANGLE/D3D). Write `1.0 - smoothstep(b, a, x)`.
- A `ShadowMaterial` or a decal a fraction of a millimetre above the floor loses the depth test inside a post-processing render target. Give it `polygonOffset`.
- A quad laid into the ground with a mirrored mapping gets culled as a back face. Use `DoubleSide`.
- One NaN pixel blacks out the whole frame through bloom. Clamp every `pow()` base in a shader.
- GTAO on a clipped (cutaway) model needs the same clipping planes on `gtao.normalMaterial`, or the cut half returns as a pale ghost.

## Sound

`sfx/` synthesises every sound in pure Python (48 kHz, reproducible) and reads the film's timeline, so sound cannot drift out of sync. `python "$SKILL_DIR/run_sfx.py" --list` shows the generators. `sample()` adds the recorded CC0 sounds in `sfx/samples/`. `sfx/score_kit.py` has the beds and accents the 3 scores use: a chord bed, a soft thud per power stroke, a motor, air under a drag.

- Every time comes from the timeline, never a typed number.
- Mastering is automatic: −14 LUFS, true peak ≤ −2 dBFS.
- Accent, never narrate: continuous motion stays silent. One key for every tonal sound.

## Taste, with numbers

- Easing: entrances `cubic-bezier(0.16, 1, 0.3, 1)`, exits `cubic-bezier(0.6, 0, 0.9, 0.35)` at half the entrance's length, state to state `cubic-bezier(0.65, 0, 0.35, 1)`. Linear only for continuous motion.
- The machine fills 60-70% of its viewport. Labels never under 34 px on a 1080 canvas.
- One accent, and it means something: the part that is working right now.
- Nothing dead-still: one element always alive.

// assembled centre of FACTS layer k: thickness below plus half its own
function assembledCentre(k) {
  let below = 0;
  for (let j = 0; j < 5; j++) if (HEIGHT[j] < HEIGHT[k]) below += THICK[j];
  return below + THICK[k] / 2;
}

// Find the layer table the model exports, wherever it lives.
function layerTable() {
  for (const v of Object.values(M)) {
    if (Array.isArray(v) && v.length === 5 && v.every((x) => x && typeof x === 'object')) return v;
  }
  for (const v of Object.values(M)) {
    if (v && typeof v === 'object' && !Array.isArray(v)) {
      const vals = Object.values(v);
      if (vals.length === 5 && vals.every((x) => x && typeof x === 'object')) return vals;
    }
  }
  return null;
}
const thicknessOf = (o) => {
  for (const k of Object.keys(o)) if (/thick/i.test(k) && typeof o[k] === 'number') return o[k];
  return undefined;
};
const nameOf = (o) => (typeof o.name === 'string' ? o.name : o.layer || o.label);

// Resolve how the model identifies a layer: FACTS index, name, height index or
// the table entry. Chosen by which convention reproduces the assembled centre.
const table = layerTable();
const CONVENTIONS = [
  (k) => k,
  (k) => NAMES[k],
  (k) => HEIGHT[k],
  (k) => (table ? table[k] : undefined),
];
const toArg = (() => {
  for (const c of CONVENTIONS) {
    try {
      if (NAMES.every((_, k) => {
        const v = M.layerCenterMm(c(k), 0);
        return typeof v === 'number' && Math.abs(v - assembledCentre(k)) < 1e-6;
      })) return c;
    } catch { /* try the next convention */ }
  }
  return CONVENTIONS[0];
})();
const centre = (k, t) => M.layerCenterMm(toArg(k), t);
const NONE = null;

function parseNum(s) {
  const m = String(s).match(/-?\d+(?:\.\d+)?/);
  assert.ok(m, `no number in ${JSON.stringify(s)}`);
  return Number(m[0]);
}

// Normalise gaugeReadout to { temp, hydration, battery, day } strings.
function gauges(api, h) {
  const r = api.gaugeReadout(h);
  if (Array.isArray(r)) return { temp: r[0], hydration: r[1], battery: r[2], day: r[3] };
  const out = {};
  const keys = Object.keys(r);
  const pick = (re, i) => (keys.find((k) => re.test(k)) ?? keys[i]);
  out.temp = r[pick(/temp|skin/i, 0)];
  out.hydration = r[pick(/hydr/i, 1)];
  out.battery = r[pick(/batt/i, 2)];
  out.day = r[pick(/day|wear/i, 3)];
  return out;
}

function lift(api, k, t, focus) {
  const r = api.focusTransform(toArg(k), t, focus === NONE ? NONE : toArg(focus));
  if (Array.isArray(r)) return { lift: r[0], aside: r[1] };
  const keys = Object.keys(r);
  const lk = keys.find((x) => /lift|vert|^y|dy/i.test(x)) ?? keys[0];
  const ak = keys.find((x) => /aside|horiz|^x|dx/i.test(x)) ?? keys[1];
  return { lift: r[lk], aside: r[ak] };
}
function opacity(api, k, focus, xray) {
  const r = api.materialState(toArg(k), focus === NONE ? NONE : toArg(focus), xray);
  return typeof r === 'number' ? r : r.opacity;
}

  const c = [1, 3, 5].map((i) => parseInt(hex.slice(i, i + 2), 16) / 255)

# Teardown

One machine, one page. The visitor sees the thing run, presses a button, and the part doing the work opens up while the gauges around it read the real numbers. Left alone, the page tours itself with a cursor. The same code records a film of the tour, frame by frame, with a score built on the same timeline.

`SKILL_DIR` below is the folder this file lives in. Builds and renders go to `./teardown-out` of the folder you run from.

## First run

```
cd "$SKILL_DIR" && npm install && npx playwright install chromium
```

The pages need nothing else. The video needs `ffmpeg` on PATH and the score needs Python 3 (standard library only). Set `FFMPEG`, `PYTHON` or `CHROMIUM` to point at other binaries.

## The 3 examples

Build one, open the HTML, press buttons. Copy the closest one when you start a new machine.

| | The machine | What drives it | Worth stealing |
|---|---|---|---|
| `v8-*` | A cross-plane V8 with glass liners: the charge burns inside the cylinder you track, valves lift on their cams, 8 pistons move from the exact slider-crank. | Crank angle. Firing order 1-8-4-3-6-5-7-2, a chamber pressure model for the indicator diagram. | Cutaway modes (glass, section, solid), the firing order as a cylinder picker, live charts synced to the crank. |
| `cessna-*` | The Cessna 337 main landing gear folding into the airframe on takeoff and dropping on landing. | Stroke 0..1: a 201 mm rack turns a 32-tooth pinion (module 4 mm) through exactly 180°. | One degree of freedom posing a whole mechanism, flight phases as functions of time, a runway that rolls under the model. |
| `strandbeest-*` | Theo Jansen's Strandbeest, 20 legs on one crankshaft, walking broadside over sand. | Wind. The crank speed is integrated from it; every joint follows by circle intersection from Jansen's 11 link lengths. | An exact linkage solver in 67 lines, instanced tubes, foot traces, a contact chart of all 20 feet. |

Each comes in 3 folders: `<name>-shared/` holds the machine, `<name>-film/` the recorded tour, `<name>-live/` the page you drive.

## How a machine is built

One folder per machine, split by job. The examples follow this exactly:

| File | Job |
|---|---|
| `kin.js` / `gear.js` / `jansen.js` | The math. Real dimensions in real units, one input (crank angle, stroke, wind) and every pose and readout as a function of it. No three.js in here. |
| `engine.js` / `gear.js` / `beast.js` | The geometry, built from code: lathed parts, tubes, instanced links. `update(input)` poses it. |
| `stage.js` | Studio, lights, shadows, post (GTAO, bloom). `frame(state, cam)` draws one frame. |
| `console.js` | The overlay: fixed 1600 x 900 CSS layout of panels, charts, toggles, callouts with leaders. `update(state)` redraws it from the frame's state. |
| `film.js` | A `SCRIPT` of operator moves (views, isolate, cutaway, throttle) and `render(t)` as a pure function of time. |
| `live.js` | The same machine in real time: buttons, sliders, orbit, zoom, keys. With no input it plays `film.js`'s script as an auto tour with a cursor; any click, drag, wheel or key hands control over, 25 s of quiet hands it back. |
| `score.py` | The sound on the film's timeline. |

For a machine outside `SKILL_DIR`, make a folder with a `main.js` and import the kit by name: `import {runSim} from 'teardown-kit/runtime.js'`. Build it with `node "$SKILL_DIR/sims/build.mjs" ./my-machine`.

## Rules that decide whether it works

1. **Start from a reference, never from imagination.** A photo, a cutaway drawing from a manual, a clip of the real thing. Build against it and compare frame by frame. Machines invented from a sentence come out generic every time; the same model rebuilds a real one closely when it has something to match.
2. **Real numbers, one source.** Get the real dimensions first (bore, stroke, tooth count, link lengths). Every gauge, chart and label reads from the same function that poses the parts, so nothing on screen can disagree with the motion. Check one by hand: in the Cessna, 32 teeth × 4 mm module is a 128 mm pitch diameter, and half its circumference is the 201 mm stroke.
3. **One input drives everything.** Pose from the crank angle, the stroke or the wind. Nothing is keyframed by hand, so the film, the live page and the score never drift.
4. **The part doing the work opens up.** Isolate it, cut it, x-ray it. A camera that goes inside is worth more than ten orbits.
5. **Light studio, one accent.** Pale backgrounds read in a feed; dark ones lose the first second. The accent marks the thing that is changing. Watch near-white parts on a pale backdrop: give them an ink outline or a darker ground.
6. **Pick the camera for the mechanism.** A planar linkage seen face-on collapses into a lattice; a 3/4 view along the spine keeps every leg readable.
7. **Fix collisions with a number.** When a part pokes through another, scale or move it in the parameter block. Never hide it with the camera.

## Live page rules

- **Test on an integrated GPU.** A page that runs at 60 fps on a desktop card can drop to 15 fps on a laptop's built-in one. The examples carry quality tiers (`TIERS` in `live.js`): no AO, lower pixel ratio, smaller shadow maps, panels redrawn every other frame. Find the expensive shader first: a displacement computed 5 times per vertex costs more than every tier together.
- **Warm the shaders.** `kit/warm.js` compiles every program in parallel before the first frame, so the page never freezes on first draw.
- **Keep the page under 1 MB.** Link crawlers (X, Slack) read the share card from the HTML and give up on a 15 MB page. Big models go out as files next to the page: `build.json` → `{"external": {"heavy.glb": "light.glb"}}`.

## render(t) contract

```js
import {runSim} from '../kit/runtime.js';

const DEFAULTS = {duration: 20, fps: 60, hud: {enabled: false}, director: {enabled: false}};

runSim(DEFAULTS, async ({cfg, canvas, capture}) => {
  // build the scene, precompute anything stateful
  return {render(t) { /* draw frame t from scratch */ return {}; }, resize() {}};
});
```

- `render(t)` is pure: no `Math.random` (use `rng(seed)` from `kit/util.js` at setup), no `Date`, no state carried between frames. Capture calls it at arbitrary times.
- Anything that moves by its own rules (agents, particles) is simulated once at load into typed arrays; `render` only reads them. A quantity integrated over time (the Strandbeest's crank under a changing wind) is integrated in closed form or tabulated at load.
- Every beat goes into `<name>-film/timeline.json` in seconds. The score reads the same file.
- Frame 0 is the thumbnail. It must already show the machine.

## Review loop

You cannot watch the video; you can look at frames. Never report a machine as done without reading sheets of the current render.

1. `--stills beats`: one tile per timeline beat, 0.3 s after it, each labelled `t=`.
2. Read every tile against the checklist below.
3. Zoom in: `--stills every:0.2 --from A --to B` for a transition, `--still T` for one full frame.
4. Fix, rebuild, go back to 1. Stop when a full pass finds nothing.
5. Final: `node "$SKILL_DIR/sheet.mjs" --video <final.mp4> --timeline <timeline.json>` and read that too: it shows what the encoder wrote.

Checklist:

- **The mechanism.** Every part that should touch touches; nothing passes through anything; the numbers on the panels match the pose.
- **Composition.** One focal point per frame. Nothing important within 60 px of an edge. Labels never cover the part they name.
- **Type.** Nothing clipped. The key readout reads at phone width.
- **3D.** Bloom eats detail: keep emissive layers under 1.0. Near-white surfaces blow out. Glossy metal under a low light streaks: roughness ≥ 0.45 and envMapIntensity ≈ 0.5 on big surfaces.
- **Timing.** Each state holds long enough to read: 1 s for a short phrase plus 0.25 s per word beyond three.

## three.js traps the examples already hit

- `smoothstep(a, b, x)` with `a > b` returns 0 on Windows (ANGLE/D3D). Write `1.0 - smoothstep(b, a, x)`.
- A `ShadowMaterial` or a decal a fraction of a millimetre above the floor loses the depth test inside a post-processing render target. Give it `polygonOffset`.
- A quad laid into the ground with a mirrored mapping gets culled as a back face. Use `DoubleSide`.
- One NaN pixel blacks out the whole frame through bloom. Clamp every `pow()` base in a shader.
- GTAO on a clipped (cutaway) model needs the same clipping planes on `gtao.normalMaterial`, or the cut half returns as a pale ghost.

## Sound

`sfx/` synthesises every sound in pure Python (48 kHz, reproducible) and reads the film's timeline, so sound cannot drift out of sync. `python "$SKILL_DIR/run_sfx.py" --list` shows the generators. `sample()` adds the recorded CC0 sounds in `sfx/samples/`. `sfx/score_kit.py` has the beds and accents the 3 scores use: a chord bed, a soft thud per power stroke, a motor, air under a drag.

- Every time comes from the timeline, never a typed number.
- Mastering is automatic: −14 LUFS, true peak ≤ −2 dBFS.
- Accent, never narrate: continuous motion stays silent. One key for every tonal sound.

## Taste, with numbers

- Easing: entrances `cubic-bezier(0.16, 1, 0.3, 1)`, exits `cubic-bezier(0.6, 0, 0.9, 0.35)` at half the entrance's length, state to state `cubic-bezier(0.65, 0, 0.35, 1)`. Linear only for continuous motion.
- The machine fills 60-70% of its viewport. Labels never under 34 px on a 1080 canvas.
- One accent, and it means something: the part that is working right now.
- Nothing dead-still: one element always alive.

// Shader warm-up before a live page's first frame. three.js links a program the first time something draws with it,
// and the frame waits on every one in turn: 1-2 s on a phone or an integrated GPU, and a frozen page meanwhile. Here
// all of them start at once and the page awaits them without blocking (renderer.compileAsync, KHR_parallel_shader_compile):
// the scene's materials and the ones held by post passes (GTAO, bloom, ink, output), which compileAsync never meets
// on its own because they only reach the renderer inside composer.render().
//
// A warmed program only helps when its cache key matches the one the frame asks for, so everything here mirrors the
// frame: each set compiles against the target it draws into (tone mapping, colour space), pass quads have no normals
// like three's fullscreen triangle, override materials (GTAO's normals) see the scene's lights and shadows, and the
// two settings three only fixes on its first render (PCFSoftShadowMap, OutputPass defines) are fixed first.
import * as THREE from 'three';

// three's FullScreenQuad geometry: position and uv, no normal
const TRI = new THREE.BufferGeometry();
TRI.setAttribute('position', new THREE.Float32BufferAttribute([-1, 3, 0, -1, -1, 0, 3, -1, 0], 3));
TRI.setAttribute('uv', new THREE.Float32BufferAttribute([0, 2, 0, 0, 2, 0], 2));
// a stand-in for the scene's meshes under an override material
const MESH = new THREE.PlaneGeometry(1, 1);

// every material a pass holds directly or in an array (GTAOPass, UnrealBloomPass, ShaderPass, OutputPass)
const materialsOf = (pass) => Object.values(pass).flatMap((v) => (v?.isMaterial ? [v] : Array.isArray(v) ? v.filter((m) => m?.isMaterial) : []));
// drawn over the scene's own meshes instead of on a quad
const isOverride = (m) => m.isMeshNormalMaterial || m.isMeshDepthMaterial || m.isMeshDistanceMaterial;

/**
 * jobs: [{scene, target}] or [{materials, target, lights, override}]; target null is the canvas, lights a scene whose
 * lights apply, override true for materials drawn as scene.overrideMaterial whatever their type.
 */
export function warmUp(renderer, camera, jobs) {
  // three swaps the removed PCFSoftShadowMap for PCFShadowMap inside its first shadow render, after any warm-up
  if (renderer.shadowMap.type === THREE.PCFSoftShadowMap) renderer.shadowMap.type = THREE.PCFShadowMap;
  const prev = renderer.getRenderTarget();
  const waits = jobs.map(({scene, materials = [], target = null, lights = null, override = false}) => {
    let root = scene;
    if (!root) {
      root = new THREE.Scene();
      for (const m of materials) root.add(new THREE.Mesh(override || isOverride(m) ? MESH : TRI, m));
    }
    renderer.setRenderTarget(target);
    return renderer.compileAsync(root, camera, lights);
  });
  renderer.setRenderTarget(prev);
  return Promise.all(waits);
}

/** The scene and every enabled pass of an EffectComposer; the last pass draws to the canvas when the composer does. */
export function warmComposer(renderer, composer, scene, camera, jobs = []) {
  const target = composer.renderTarget1;
  const passes = composer.passes.filter((p) => p.enabled);
  const last = composer.renderToScreen ? passes[passes.length - 1] : null;
  // OutputPass picks its defines from the renderer on its first render: run that part now, with the draw left out
  for (const p of passes.filter((x) => x.isOutputPass)) {
    const quad = p._fsQuad;
    p._fsQuad = {render() {}};
    p.render(renderer, composer.renderTarget2, composer.renderTarget1);
    p._fsQuad = quad;
  }
  const mats = passes.filter((p) => p !== last).flatMap(materialsOf);
  return warmUp(renderer, camera, [
    {scene, target},
    {materials: mats.filter((m) => !isOverride(m)), target},
    {materials: mats.filter(isOverride), target, lights: scene},
    {materials: last ? materialsOf(last) : [], target: null},
    ...jobs,
  ]);
}
